# 교재 제작 가이드 (Claude 인계용)

> 이영우T(이음학원)와 함께 MathDB 문제은행으로 PDF 교재를 만드는 작업의 누적 노하우.
> **다음에 교재를 만들 때 Claude 가 이 문서만 읽고 바로 이어받도록** 정리. 시행착오로 알아낸
> 함정이 많으니 새 교재 전에 5~9장(함정/뷰어/체크리스트) 먼저 볼 것.

---

## 1. 한눈에 보기

```
SQLite(db/mathdb.sqlite) / cloud Postgres(SUPABASE_DB_URL)
   └─ questions / solutions / images
        │  scripts/build_*.py 가 조회·정렬·필터
        ▼
app/pdf_engine.py  (HTML+CSS → Chromium/Playwright 인쇄 → PDF, KaTeX 수식)
        │  cover.pdf / dividers.pdf / problems.pdf / quick_answer / solutions
        ▼
scripts/merge_*.py 또는 build_*  가 PyMuPDF(fitz)로 병합
        ▼
output/<프로젝트>/<교재>.pdf   (리포 내 최종본)
        ▼
scripts/lib_deliver.py  deliver()  →  ~/클로드교재/  (+ xattr -c)
```

- **데이터**: `questions`(question_text/choices/answer/points/chapter/difficulty/has_image/region/grade…), `solutions`(FK), `images`(image_ref→R2 URL, image_type=problem|solution).
- **수식**: question_text 에 `$...$` LaTeX 인라인. KaTeX 가 렌더(throwOnError:false).
- **그림**: 본문 `<<IMG:imageN>>` 플레이스홀더 → images 테이블의 R2 URL `<img>` 임베드.
- **조건박스**: `<<BOX_START>>...<<BOX_END>>` → 보기/조건 박스 HTML.

## 2. 교재 시리즈(브랜드)와 빌더

모두 "○○ POINT" 브랜드. 표지/디바이더/머리말 톤은 통일(화이트+네이비잉크+블루액센트, 이영우T 중앙하단).

| 브랜드 | 정체 | 메인 빌더 | 산출물 |
|---|---|---|---|
| **KERNEL POINT** | 내신기출 빈출 유형(고2 대수 등). A·NN 번호 + 1·2·3차/OX 체크 + KEY POINT + MEMO + 우측 PART 인덱스 | `build_kernel_point_book.py`(단독, 표지+디바이더+본문+해설 한 방), `merge_kernel_book.py`, `merge_daesu_kernel.py` | `대수 1학기 기말 KERNEL POINT.pdf`, `KERNEL_POINT_대수_빈출FINAL.pdf`, `KERNEL_POINT_3-1_기말대비.pdf` |
| **SUMMIT POINT** | 모의고사 정복 스타일. 2단 문제 + 통합 빠른정답 + 래스터 해설 | `build_gwangbuk_book.py`, `merge_summit_book.py`, `make_summit_point_*` | `광북_1-1-b_SUMMIT_POINT.pdf`, `SUMMIT_POINT_모의고사_완전정복.pdf` |
| **BASIC POINT** | 기본/표준 유형 교재 | `build_basic_point_final.py`, `make_cover_basic_point.py`, `make_chapter_pages.py` | `BASIC_POINT_대수_1학기기말.pdf` |
| **TEXTBOOK POINT** | 중단원 평가(단원별) | `build_jungdan_*`, `merge_jungdan_book.py` | `TEXTBOOK_POINT_대수_1학기기말대비.pdf` |
| **필수유형 FINAL** | 흰배경 모던 표지의 마무리 교재 | `make_daesu_final.py` | `대수_1학기기말_필수유형FINAL.pdf` |
| study_book 하/중 | 난이도 분책(공수1 하/중 대기 중) | `output/study_book/` | `study_book_하.pdf`, `study_book_중.pdf` |

빌드 패턴은 보통 **부품 따로 → 병합**:
`make_*_cover.py`(표지) + `make_*_dividers.py`(챕터 디바이더) + `build_*` (본문/빠른정답/해설) → `merge_*.py`(fitz 병합) → `deliver()`.
KERNEL POINT 만 `build_kernel_point_book.py` 단일 스크립트로 전 과정 처리(가장 최신·완성형, 새 교재의 레퍼런스로 삼기 좋음).

## 3. pdf_engine.py 핵심 진입점

- `generate_book_pdf(questions, title, subtitle, include_source, overrides, logo_path, divider_*, cover_*, page_running_left, …)`
  — 표지+챕터디바이더+본문(2단)+빠른정답+해설을 한 HTML 로 만들어 PDF bytes 반환. **교재 모드의 단일 진입점.** `include_difficulty=True` 경로가 곧 KERNEL POINT 의 `book-kp` 메모 레이아웃.
- `render_question_body(text, images)` — 본문 HTML. `_normalize_boxes` + `<<IMG>>` 임베드 + None 가드 + `img_check` 배지(합성이미지 의심).
- `format_choices(choices_json, book_mode)` / `_choice_col_class()` — 선지 렌더. 선지 시각길이>13 → `cols2`, 아니면 `cols3`(5지선다 기본 3/2 배열). 잘못 파싱된 부분선지(`[3,4,5]`)는 빈 문자열로 억제.
- `_render_slot(i, q, layout, …)` — 한 문항 슬롯. `book-kp` 면 A·NN 헤더 + 체크박스 + 본문 + 선지 + **KEY POINT + MEMO(줄)**.
- `_render_chapter_divider`, `_render_book_page_head`(머리말), `_render_book_page_side`(우측 PART/letter 인덱스), `_render_quick_answer_table`(빠른정답, 오렌지 번호), `_render_solution_items`(해설).
- 수식 보호/정규화: `_with_math_protected`(=`$...$` 를 placeholder 로 빼서 변형 후 복원, **복원 시 `<>&` HTML escape** 필수), `_normalize_math_text/_inner`(여러 줄 수식 합치기, `sin`→`\sin`(단 `\text{}`/`\mathrm{}` 안은 제외), 미닫힘 `$` 보정).

`overrides = {qid: "full"}` 로 문항별 레이아웃 지정(KERNEL POINT 는 전 문항 full = 한 단에 한 문제).

## 4. KERNEL POINT 본문 레이아웃(book-kp) 상세

페이지 = `.bp-page`(section). 안에 머리말(`.bp-head`) + 본문영역(`.page-body` flex row) + 우측 인덱스(`.bp-side` absolute) + 2단(`.col` × 2, 각 `.slot.book-kp`).
슬롯 = A·NN + 1/2/3차·O/X 체크 + 출처메타 + 본문 + 선지 + 하단 KEY POINT 박스 + MEMO(줄들).

- 선지 동그라미 색 `#111`(검정), 우측 인덱스 여백 축소(`.bp-page { padding:0 13mm 0 0 }`, `.bp-side{right:2mm}`).
- 조건박스 표가 단 폭 넘으면 `font-size:0.8em` + `overflow:hidden` 로 맞춤.

## 5. 인쇄(Chromium) 레이아웃 함정 — **가장 중요**

1. **페이지 바닥까지 채우기는 `vh` 만 먹힌다.** Chromium PRINT 는 안쪽 요소의 `flex:1`·`min-height`·`mm/% height` 높이채움을 전부 무시(스크린은 됨) → 컨테이너가 콘텐츠 높이로 수축. 해결: 페이지 박스에 **고정 `height:100vh`(=본문영역≈275mm 기준) + `display:flex;flex-direction:column` + `overflow:hidden`**, inner `flex:1` 체인이 그 높이까지 자람, `margin-top:auto` 로 하단 앵커. MEMO 하단여백 40mm→10mm 해결한 방식.
   - ⚠ `min-height:100vh` 로 주면 긴 문제에서 박스가 본문영역을 넘게 자라 **빈 페이지** 생김 → 반드시 고정 `height`. `overflow:hidden` 이 넘치는 끝줄을 바닥에서 절단(짧은본문=메모 많이/긴본문=적게 자동 적응).
2. **수식의 `<` `>` 는 반드시 HTML escape.** 부등식 `$a<t<b$` 의 `<`,`>` 를 그대로 두면 브라우저가 태그로 파싱 → DOM 붕괴(본문 좁아짐/깨짐). `_with_math_protected` 복원 시 `&lt;&gt;&amp;` 치환.
3. **`@page { size:A4; margin:10mm 10mm }`** → 본문영역 277mm. 페이지 높이 채움 계산의 기준.

## 6. PDF / 뷰어 함정 — **신규 교재 배포 전 필독**

1. **Type3 폰트 과부하 → Acrobat/Preview 4페이지부터 빈화면.** KaTeX 수식을 Chromium 이 Type3 폰트로 임베드(페이지당 40+) → 뷰어 렌더 실패. **해결: 각 페이지를 래스터화(180dpi JPEG)** 해서 재구성(`fitz` get_pixmap → 새 페이지 insert_image). 텍스트 선택은 포기, 벡터본은 `output/...vector.pdf` 로 따로 보관.
2. **래스터 저장은 단순하게: `out.save(path, garbage=4, deflate=True)` 만.** `gs 재증류`·`clean=True` 를 넣으면 **Acrobat 에서 1페이지부터 빈화면**(렌더 실패) 됨 — 절대 쓰지 말 것.
3. **"PDF 안 열림/빈화면" 진짜 원인 1순위 = macOS 격리(quarantine).** Acrobat 으로 한 번 열면 파일에 `com.apple.quarantine(...;AdobeAcrobat;)` + `OpenWith=Acrobat` 확장속성이 붙어, 이후 Gatekeeper 가 **모든 뷰어에서** 차단(빈화면/"악성코드 확인 불가"). 파일은 멀쩡(Quicklook·fitz 렌더됨). `xattr -l <파일>` 로 확인 → **`xattr -c <파일>`** 로 제거.
4. **그래서 교재는 다운로드 폴더에 두지 않는다.** 다운로드는 Gatekeeper 가 격리를 제일 적극 붙임. 라이브러리 = **`~/클로드교재`**(다운로드 밖). 다운로드 폴더엔 `~/클로드교재` 심볼릭 링크가 있어 한 번 클릭 진입. 기본 PDF 앱은 **Preview 권장**.
5. **전달은 `scripts/lib_deliver.py` 의 `deliver(OUT_PDF)`** — `~/클로드교재` 복사 + `xattr -c`. 새 교재 빌더는 마지막에 `from lib_deliver import deliver; deliver(OUT_PDF)` 한 줄 호출할 것(이미 7개 빌더 연결됨).

## 7. DB 콘텐츠 보정(프로덕션 적용 완료 이력)

300+ 강사 공동작업 HWPX 라 잡티가 많아 prod DB 를 전수 보정함(스크립트 보존):
- `fix_latex_dollars.py` — 미닫힘 `$` 복구, 함수명 정규화 등(q 25,494 + s 31,897행).
- `strip_editorial_memo.py` — 본문에 섞인 편집 오검 메모(`[NNNN]오검`/`<수정사항>`/sign-off) 제거. **마커 위치부터 절단**(줄시작 아님), 정리 후 빈 본문은 보존.
- `wrap_hangul_math.py` — 수식 속 한글을 `\text{}` 래핑(KaTeX 전후 검증). CLEAR 자동적용, AMBIG 는 review json.
- `detect_composite_images.py` — 4-in-1 등 합성 이미지 의심 qid → `output/composite_image_qids.json` → 본문 `⚠ 그림 확인 필요` 배지.
- `audit_latex_dollars.py` — 읽기전용 감사.

원본 HWPX 가 그림 4개를 1장 합성 이미지로 저장한 경우는 파서/빌더 버그 아님 → 자동분할 불가, 배지로만 표시.

## 8. 작업 규칙(이 프로젝트 합의)

- **난이도 정렬**: 하<중<상<킬 (`DIFF_ORDER`). KERNEL POINT 는 '상' 제외(사용자 지시) 같은 필터를 빌더에서.
- **중단원명 정규화**: `CHAPTER_NORMALIZE`(parse_hwpx). "다항함수"→"이차함수" 통일. 신규 변형은 **사용자 확인 후** 추가.
- **/근본 워크플로우**: 작업 후 5회 검수(메인3+서브2) → 이상 없으면 커밋. 민감파일(.env*) 섞이면 중단.
- **커밋**: 한국어 간결("무엇을/왜"), 끝에 `Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>`. 무관 파일·`.env.save` 제외. 푸시는 사용자 요청 시만.
- **컴팩션 대비**: 이미지·에러는 받자마자 핵심을 텍스트로 받아쓰고 진행.
- **HWPX 적재 차수**: 차수 갱신은 사용자 명시 시에만.

## 9. 새 교재 만들 때 체크리스트

1. **데이터 범위 확정**: region/grade/chapter/difficulty 필터, 정렬(단원→난이도→qid). 빌더 상단 상수로.
2. **브랜드/레이아웃 선택**: KERNEL POINT(메모형) / SUMMIT(모의고사) / BASIC / TEXTBOOK / FINAL. 표지·디바이더·머리말 톤 통일.
3. **`generate_book_pdf` 파라미터** 채우기(cover_*, divider_*, page_running_left, overrides).
4. **수식/박스/그림 확인**: `_normalize_*` 통과? `<>` escape? `<<IMG>>` 매칭? 합성이미지 배지?
5. **벡터본 측정**: `fitz` 로 빈 페이지·메모 하단여백·본문 클리핑 점검(짧은/긴 본문 페이지 렌더 확인).
6. **래스터화**(뷰어 호환): 180dpi JPEG, 빈 페이지 skip, 저장은 `garbage=4,deflate=True` 만(gs/clean 금지).
7. **`deliver(OUT_PDF)`** 로 `~/클로드교재` 전달(+xattr 자동제거).
8. **/근본** 검수 후 커밋.
